# subagent

把一个有明确范围的任务交给独立 Pi SDK 会话，**等待本次执行结束、返回结果、释放会话**。

这是一次性前台委派。每次调用都创建新会话，任务与必要上下文由本次参数明确提供。

## 30 秒上手

1. **直接调用**：省略 `subagent_type` 即通用 agent。

```json
{
  "description": "检查授权变更",
  "prompt": "只读审查 extensions/example 的当前补丁，给出文件位置与可复现依据。不要修改文件。"
}
```

2. **使用自定义定义**：复制 [`examples/reviewer.md`](examples/reviewer.md) 到 `~/.pi/agent/agents/reviewer.md`，再在调用里加上 `"subagent_type": "reviewer"`。

3. **填写真实模型**：示例中的 `model` 行默认注释；需要固定模型时填入 `/model` 中真实存在的 `provider/modelId`，留空继承父模型。`thinking` 只接受 `off / minimal / low / medium / high / xhigh / max`。

新增定义后可立即按名字调用；工具描述里的 agent roster 在扩展加载时生成，新增或修改定义后需在父端 reload 才会刷新该列表。

## 何时委派

工具描述说明能力与执行边界，父端 `promptGuidelines` 集中表达触发策略：

- **调查更积极，写入仍保守。** 非简单任务中，默认优先把可分离、有边界的工作交给子代理，不必等用户点名 `agent`。
- 明确的触发场景包括：跨模块或多问题调查、独立复核/验证、单独故障假设、可并行的只读探索。优先考虑能减少父端大量独立探索或验证工作的委派；是否需要多轮工具调用本身不是判断标准。一次查找、一个小修、依赖当前对话全貌的工作直接做。
- 任务拆成多个独立问题时，优先在同一批并行委派，而不是在父端串行处理。用户明确禁止委派时必须遵守。
- 实施委派需要清晰、不重叠的写入范围和真实的并行/上下文收益；共享契约、重叠写入和最终集成交回父端。快速概览、小修复、例行检查和强耦合实施仍直接完成。父端只能传递额外工具，不能通过工具列表撤销子会话的基础工具；工具可用不等于操作获准。
- 按问题与交付划分，不按文件数量硬拆，不拆碎简单工作，不设调用配额，也不默认追加一轮 reviewer。
- 主代理负责整体决策、共享契约、集成和最终验收。子代理报告首行必须是 `Completed`、`Partial` 或 `Blocked` 之一；`Partial` 表示已有进展但仍不完整或未验证，`Blocked` 表示因缺少输入/授权/决策或环境、工具故障而无法继续。用户明确限制委派时必须遵守；允许使用工具不等于允许扩展任务或写入范围。

这些是模型选择工具的提示策略，不是自动路由器、固定调用配额或行为保证，也不提供自动资源锁或强制只读。主代理需给出路径、外部系统、副作用的授权范围；实施权限不自动包含破坏性操作、部署或外部系统变更。

## 工具：`agent`

```json
{
  "description": "检查授权变更",
  "prompt": "只读审查 extensions/example 的当前补丁。检查权限绕过和错误处理，给出文件位置与可复现依据。不要修改文件。",
  "subagent_type": "reviewer"
}
```

必填参数：

- `description`：工具行显示的简短工作说明。
- `prompt`：独立完整的任务，包含目标、必要上下文、读写范围和验收条件。

可选参数：

| 参数 | 作用 |
|---|---|
| `subagent_type` | 使用 agent 定义；省略为通用 agent |
| `tools` | 在默认/定义工具基础上追加完整工具名，例如 `["lark_doc"]`；不是全部工具的权限上限或只读开关 |
| `model` | 覆盖模型，格式 `provider/modelId` |
| `thinking` | 覆盖思考等级，由 SDK 适配模型能力 |
| `max_turns` | 按次覆盖轮次上限；达到后先要求收尾，再给 5 轮宽限。省略时用定义值，未定义则无上限 |
| `inherit_context` | 显式启用后附带最近最多 20 条 user/assistant 文本作为低信任 JSON 背景；默认关闭，优先最小任务摘要。序列化字符预算 24,000：优先丢弃较旧消息，最新消息过长时截断并标注 |

上下文摘录不是 fork，不包含工具调用、结果或图片，也不替代任务本身的约束与证据。摘录按序列化后的 JSON 字符数（含结构转义）有界，超出时保留最近的连续消息；不会为了塞进更多旧消息而跳过较新的记录。最新消息过长时从尾部截断并保留标注；预算小到连标注都放不下时 JSON 数组为空，裁剪提示仍然保留。截断按 UTF-16 码元回退，不会留下破损的代理对。消息以 JSON 记录序列化，转义可能伪造结构的字符；角色与内容都是引用数据，不能扩展任务或授予权限。仓库内容、工具输出也不能自行扩权；缺失截图或工具结果时不能假定已见到证据。

结构化只能减少边界混淆，不能消除语义提示注入。默认不继承摘录；确有必要才启用，并避免无关敏感内容，尤其在覆盖模型/供应商时。这里没有自动脱敏或摘要机制，必要证据仍应筛选后写入任务。

## 结果与取消

调用等待本次执行结束后返回结果：

- `finished`：执行正常结束；不等于父代理可以跳过验收。
- `failed`：初始化、模型或执行失败；保留已产生的部分输出。
- `aborted`：父调用取消（`cancelled`）、轮次上限耗尽（`turn_limit`，结果会带回 `max_turns`），或 SDK 自身中止（`sdk_abort`）；保留部分输出。

任务报告的 `Completed / Partial / Blocked` 与运行时执行状态分开：正常 `finished` 也可能报告 `Blocked`，不能据此认定验收通过。TUI 将 `finished` 显示为 `returned`，只表示调用已返回。调查本身达到验收要求即可 `Completed`，即使调查发现缺陷。

失败和取消均使用错误结果标记，不伪装成完成。shutdown handler 超时、拒绝，或 `session.dispose()` 抛错时，会写入 `cleanupWarning`，不会被静默吞掉。最终回合没有文本时，返回最后一段助手文本并标注 `[no final text: ...]`，不把它伪装成最终报告。工具结果的 `details` 保存状态、tokens、工具次数、解析后的 `agent` 配置和完整输出路径，供 UI 在 reload 后渲染。工具行维持子助手回合的 tokens/cost 口径；返回给 Pi 的 `usage` 则汇总本次新会话的助手、子工具、压缩及其他推理条目，避免漏掉嵌套用量。

父调用的取消会传播到排队或运行中的子任务。排队取消不会创建会话。运行中的取消会调用 SDK abort，并给其最多 5 秒合作收尾；不响应取消时会返回明确的 `cleanupWarning`。扩展关闭另有独立的 5 秒界限，不承诺整个调用在 5 秒内结束。直到结果准备完毕，取消仍优先于迟到的成功回执，包括 shutdown 或结果文件输出阶段。

**进程内取消不是强制终止。** 忽略信号的工具或初始化可能仍在收尾，已执行的文件修改或远端操作不会被撤销。迟到创建的会话仍会被关闭。

## 长结果

默认内联预算为 **12,000 字符**（JavaScript UTF-16 code units）。超过预算时：

1. 把完整可读正文保存成 UTF-8 `.txt` 文件；
2. 内联返回前缀、截断提示和绝对路径；
3. 父代理通过普通 `read` 按需读取完整正文。

文件位于 `<agent-dir>/subagent-results/<cwd-group>/`，不会默认写入项目目录，也不是需要解析的 SDK JSONL。文件名唯一，以排他方式创建，不覆盖旧结果。写入失败会明确报错；若有 SDK 转录，会给出其诊断路径，不虚构完整输出文件。

结果文件和转录不会随内存会话释放而删除；目前没有自动磁盘清理策略。它们可能包含代码、工具输出等敏感内容，应按本地会话数据管理。

## Agent 定义

读取用户目录 `~/.pi/agent/agents/*.md`，以及**可信项目**最近的 `.pi/agents/*.md`。同名项目定义覆盖用户定义；不可信项目不能提供定义、项目扩展或项目设置。

```markdown
---
name: reviewer
description: 只读代码审查
tools: [read, grep, find, ls]
# model: provider/modelId   # 省略则继承父模型
# thinking: high            # off|minimal|low|medium|high|xhigh|max
# max_turns: 40             # 省略则无轮次上限
---
只读审查指定范围，只报告有证据的问题。不得修改文件。
```

可直接复制 [`examples/reviewer.md`](examples/reviewer.md)。`model` 必须替换为 `/model` 中真实存在的 `provider/modelId`，否则调用会报 `Unknown model`。缺少 `name`/`description` 或 frontmatter 无效的定义会被跳过；`subagent_type` 未命中时，错误会附带 `Ignored definitions: <path> — <reason>`。非法的 `thinking` 会直接报错并列出合法等级。

支持 `tools`、`disallowed_tools`、`model`、`thinking`、`max_turns`。**定义中的**显式 `tools: []` 在父调用没有追加工具时表示没有工具，不会退回默认配置；与调用参数 `tools: []` 的“不追加”不同。`max_turns` 可选，**默认没有轮次上限**；达到上限时先要求收尾，再给 5 轮宽限，仍未结束才取消。

默认提示和自定义提示都会保留适用的上下文指令，并附加统一的子代理范围与交付约定。定义的 Markdown 正文作为**附加指令**并入标准系统提示，不会替换工具清单、默认规则与文档段。若用户或受信项目另有 `SYSTEM.md`，SDK 会以它作为自定义 preamble，此时标准段本身不生成；定义正文仍只追加。

## 工具授权与信任

- 子会话不自动继承父会话的所有扩展，只加载任务或定义明确需要的扩展。
- 请求的扩展若在**启动阶段**（`session_start` / `resources_discover`）报错，本次调用失败并释放会话，避免父端误以为工具已生效；`register_mcp_server` 这类“已注册但无人连接”的告警不在此列。
- 定义工具与父调用额外工具按现有合并规则解析，最终交给 SDK 的是完整普通白名单；没有请求的同扩展工具、动态工具不能借 codemode 或 tool search 绕过授权。
- settings 的 `defaultTools` 只决定内置工具 baseline，不隐式授权扩展工具。
- 隐式内置工具固定为 SDK 实现，避免顺带加载的扩展同名覆盖；明确授权的 core 名称仍可采用刻意选择的扩展实现。若父端注册表显示该 core 名由扩展覆盖，子会话会验证覆盖确实注册；扩展加载成功但没有注册该工具时调用失败，不会静默回退到 SDK 内置实现。
- MCP 使用实际完整工具名授权；未授权的 `mcp__*` 与三个资源工具会额外排除，关闭 SDK 的白名单豁免。授权 `read_mcp_resource` 不是单服务器资源隔离。
- 扩展通过 `pi.registerMcpServer()` 动态注册的服务器，会按所选 MCP 工具携带配置快照到子会话，不为此重新执行来源扩展；若其他工具授权已显式加载来源扩展，则保留其注册所有权。资源工具会携带全部动态服务器。服务器配置仍受 `mcp.json` 的同名覆盖规则约束，携带服务器配置不会授权其余工具。
- 子会话默认排除本扩展的 `agent` / `agent_send` / `agent_result`（禁止递归委派）和 `ask_user`。其他扩展提供的委派工具不会被自动识别，需要在 `tools` 授权边界中避免授权，或用 `PI_SUBAGENT_EXCLUDED_TOOLS` 显式排除；该环境变量只追加排除项，不削弱默认策略。
- 父端模型目录与凭据 runtime 只读复用。子扩展不得注册 provider、virtual model 或改写共享认证状态。
- 同一 SettingsManager 同时交给资源加载器与 SDK，避免子会话自行放宽项目可信决定。

工具列表的两层语义（仍受拒绝列表与信任规则约束）：

| Agent 定义 `tools` | 调用参数 `tools` | 最终基础选择 |
|---|---|---|
| 未设置 | 省略或 `[]` | SDK/settings 的内置工具 baseline，通常为 read/bash/edit/write |
| `[]` | 省略或 `[]` | 无工具 |
| `[read]` | `[ls]` | read、ls |

**工具白名单不是操作系统沙箱。** 自然语言“只读”不会自动切换运行时工具模式；保留任意 Shell 或可写扩展时，不能承诺强制只读。只读任务不得产生项目持久修改或外部系统变更，测试临时/缓存应位于仓库外。前后 Git 检查只能发现可观察变化。

所有会话仍共享工作目录和文件系统。执行器只限制运行名额，不识别资源竞争或提供资源锁；文件互不相同也可能竞争 lockfile、Git 元数据、依赖、测试产物及全仓命令。并行实施前明确共享契约和所有权，冲突操作串行，或使用已获授权的隔离工作区。主代理必须检查实际变更、协调并发修改、保留无关改动并在稳定工作区验证，不能只采信子代理报告。

子代理角色约定要求缺失输入、所有权或授权时报告阻塞；commit/push/reset/stash/切分支、部署及破坏性操作不因工具可用或一般实施权限而获得授权。

## 并行与 UI

同一批独立 `agent` 调用可以前台并行，父调用仍等待结果。执行器默认最多 10 个运行调用，超出 FIFO 排队；失败不破坏兄弟调用，结束后归还名额。

### TUI 展示

- 默认恢复第一版式紧凑摘要：正常折叠卡片从首帧到结束仅一行，显示任务说明、状态和可用统计；不常驻工具行、不预留空行，也不自动展开。工具开始/结束、槽位变化和并发变化不会插入工具名称、目标或 `+N active`。异常通知和手动展开的详情额外显示。
- 说明优先，右侧以 `tokens · 工具调用次数 · 耗时 · 状态` 紧凑显示，状态始终贴右且独立着色，tokens 仅在结束后可用时显示；不为每个字段预留固定列。空间不足依次省略 tokens、调用次数、耗时，极窄屏优先保留状态并截断，始终不换成多行；完整任务与统计仍可手动展开查看。宽度为扣除宿主 outputPad 后的有效内容宽度。
- 运行时仅对有更新回调的直接 TUI 调用启用每秒计时和工具计数更新；tokens 仍只显示最终值。耗时从本次调用开始，包含排队、初始化、执行和收尾，返回结果后冻结。
- 主行在运行阶段使用 `queued / starting / running / cleaning up / preparing result`，结束后统一 `returned / failed / stopped`；取消、轮次限制和 SDK 中止分别在附加通知行显示 `cancelled / turn limit reached (max_turns=N) / session aborted`。`running`（及其他进行中状态）表示本次调用尚未返回，`returned` 不代表任务验收通过；有清理警告时主行显示 `returned (warning)` 并以警告色呈现。
- 工具明细仅在手动展开时显示工具名、安全短目标、状态及 SDK 实际提供的耗时；缺耗时不补成 0ms，也不把观察间隔冒充执行耗时。read/edit/write 显示有界路径；bash 仅把可识别的简单命令归类为常量白名单标签，如 `rg / npm test / npm run check`，不保留参数。环境赋值、包装器、脚本、复杂 shell 语法或未知命令降级为仅显示 `bash`。不展示子代理自然语言进展、完整命令、原始参数、工具输出或思考内容。
- 失败原因、取消 / 轮次限制、清理警告和报告截断在折叠态也可见；失败通知优先使用结构化 `errorSummary`，缺少时从当前结果正文首行提取，不伪造耗时或配置。
- 沿用宿主工具展开 / 收起操作（默认 `Ctrl+O`，以实际绑定为准）。运行中展开按“activity → 调用配置 → 完整委派任务”显示，不生成空的 report；返回结果后按“report → 完整报告路径（如有）→ activity → 调用配置 → 完整委派任务”显示低对比度竖向详情轨道。报告使用 Markdown；宽度不足时省去轨道以保留正文空间。
- 手动展开的 `activity` 保留最近 5 次顶层工具调用，并补入不在最近窗口中的快照槽位记录，最多 7 条；未收到结束事件的记录标为 `unfinished`，不宣称工具已停止。计数仍以子助手发出的调用为准，不把工具内部嵌套调用混入现有统计。只读取当前 version 2 进度快照；不兼容旧版快照、不从调用次数或名称采样编造记录。展开不是全量 SDK 转录，调用总数不代表已展示每次调用。
- 普通工具事件以 750ms 的最小间隔合并发布；瞬时短调用可能直接呈现完成记录，不逐事件/逐输出刷屏。顶部计时复用每秒心跳；最终结果与取消不等待合并窗口。计时器由本次 execute 持有，不在 render 中启动；结果返回或扩展关闭时停止所有刷新并拒绝迟到更新。观察异常不改变执行结果。非 TUI 或没有更新回调时不开启实时观测；不增加 widget、侧栏、后台任务或 codemode 嵌套卡片。
- 固定 TUI 文案统一为英文，任务描述、prompt、报告和原始错误保留原文。分组使用 `report / full report / activity / config / description / prompt`；展开 `config` 先显示解析后的 `agent / model / thinking / tools`（追加工具标注 `(add)`），再显示调用参数中的 `model override / thinking override / additional tools`，追加工具保留权限边界说明。调用计数区分 `1 tool call / N tool calls`。报告中的 `Completed / Partial / Blocked` 仍是子代理自报结论。
- 展开不会自动读取已落盘的完整报告；截断结果保留完整路径与 `read` 提示，折叠态直接显示 `ctrl+o for path`。展示不改变模型收到的文本、前台等待 / 取消语义或结果落盘规则；经 codemode 嵌套调用时仍由 codemode 展示其调用摘要。

## 实现边界

```text
index.ts                    工具入口与渲染适配
    ↓
src/request.ts              定义、模型、上下文、信任和工具选择
    ↓
src/executor.ts             可取消限流与活跃调用关闭
    ↓
src/runner.ts               SDK 创建、执行、事件记账和最终关闭
    ↓
src/outcome.ts               不含 SDK 句柄的结果数据
src/progress.ts              有界活动快照与本次调用的刷新生命周期
src/result-output.ts         内联预算与完整结果文件
```

`runner` 自己拥有 session 的创建与关闭；调用结果不含 session。扩展级只保存活跃和排队调用。

SDK 转录保存在 `<agent-dir>/subagent-sessions/<cwd-group>/`。扩展资源依次经历 `session_start`、有界 `session_shutdown`、`dispose`。事件记账不会因运行中压缩替换 `session.messages` 而丢失用量、错误或最终文本。

更新后需在父端 reload 才会替换已加载的工具注册；本包不会修改全局 settings 或自动执行 reload。

## 开发与验证

```bash
cd extensions/subagent
npm run check
```

重点覆盖一次性关闭、初始化/运行/排队取消、迟到清理、并发归还、实际 SDK 扩展生命周期、严格工具授权、可信边界、压缩后的事件记账、完整结果回读及 UI 宽度/ANSI/Markdown 属性。

测试均离线执行，无需真实模型请求或外部 MCP 服务联调。入口契约测试检查注册的描述与 Guidelines；真实 SDK 组装测试在隔离临时目录中确认这些规则进入父端提示词，不发起模型或子任务执行。

离线检查不能证明模型会按预期委派。包内独立脚本默认只生成离线计划，不读认证配置或调用模型：

```bash
npm run eval:guidance -- --model provider/modelId --case G02 --repeat 2
```

只有显式 `--live`、`--model` 和 `--max-requests` 才启用真实父模型请求；始终不执行真实子代理。脚本使用精确的纯内存 `read` / `ls`，不模拟 Bash，默认在系统临时目录生成新报告目录，不修改项目或认证配置。超时、截断、服务错误单独标记为不可判定，不算路由失败。

案例、结果字段、退出码及付费调用示例见 [委派提示词评测说明](docs/delegation-guidance-evaluation.md)。默认 `npm run check` 仅跑离线测试；此脚本不是完整 Agent 能力评测器，也不是日常全部工具环境的重放。
