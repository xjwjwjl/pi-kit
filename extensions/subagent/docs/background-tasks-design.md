# 会话内后台任务设计

> 状态：设计提案，未实现。本文不改变当前插件的工具、参数或运行行为；当前 `agent` 仍是一次性前台调用。

## 目标与范围

让父代理提交一个独立任务后继续工作，由明确的所有者负责执行、结果保存、取消和收尾，而不是仅把工具的返回时间提前。

设计采用同进程的 Supervisor / Worker 职责划分：**Supervisor 是普通代码，不是另一个负责思考或调度的模型。**

- 一次提交对应一次执行，Worker 为本次任务创建 SDK 会话，执行后释放。
- 后台任务可以跨越父代理的一次回合，但归属于创建它的父会话。
- 结果、SDK 会话和完成通知分别管理，彼此不承担对方的生命周期。
- 不做长期驻留 Agent、运行中消息、会话续聊、自动任务拆解或任务 DAG。
- 不引入 daemon、数据库或跨进程恢复；不承诺父进程退出后继续执行。

## 模块职责

```text
父代理 ──提交──▶ Supervisor ──执行──▶ Worker ──创建──▶ SDK 会话
                    ▲                  │
                    └──── Outcome ─────┘  执行并收尾
                    │
                    ├──▶ ResultStore ──▶ 独立可读的完整结果
                    └──▶ Notifier ─────▶ 父会话提示，引用已保存的结果
```

| 模块 | 负责 | 不负责 |
|---|---|---|
| Supervisor | 任务身份与归属、排队和限流、状态转换、取消请求、协调结果发布与收尾 | 推理、自动拆解任务、长期保存 SDK 会话 |
| Worker | 单次 SDK 会话的创建、执行、事件记账和释放；产出纯数据 Outcome | 决定通知时机、管理其他任务、保留会话供续聊 |
| ResultStore | 保存正文、结局、用量和必要诊断，提供独立于 Worker 的读取引用 | 从存活的 SDK 会话临时拼装唯一结果、恢复执行 |
| Notifier | 在父会话可接收的时机提示完成，携带任务标识与结果引用 | 充当唯一结果通道、改变任务结局、持有 SDK 会话 |

任务记录保存普通元数据；SDK 会话只由对应 Worker 持有。任务身份不等于可续用的 Agent 身份，读取结果不要求 Worker 继续存活。

## 所有权与取消来源

| 事件 | 设计行为 |
|---|---|
| 父代理本轮正常结束 | 已接受的后台任务继续执行 |
| 用户用 Esc 打断父代理本轮 | 不默认取消已接受的后台任务 |
| 针对任务发出取消请求 | 排队任务不再启动；执行中的任务进入合作取消流程 |
| 父会话关闭或切换、所属扩展释放 | 停止接收任务，对所属任务请求取消并进行有界收尾 |
| 父会话压缩上下文 | 不改变任务归属，也不依赖旧上下文保留完整结果 |
| 父进程退出或崩溃 | 不承诺任务继续或恢复；已保存结果文件可以保留 |

接受后的后台任务使用自己的取消控制器，不直接继承父回合的取消信号。提交接受的边界仍需在接口设计中明确，不能把接受前的取消与接受后的任务取消混为一谈。

任务和通知必须绑定原父会话；会话切换后不得把旧任务的通知注入新会话，也不能依赖已经失效的父端上下文对象继续调用 API。

## 执行与收尾

正常流程的语义阶段为：

1. Supervisor 接受任务，记录归属并排队。
2. 获得并发名额后，Worker 创建 SDK 会话并执行一次。
3. Worker 收集正文、错误、用量与清理诊断，释放会话并返回 Outcome。
4. ResultStore 保存结果；Supervisor 发布结局，Notifier 再安排提示。

这些是职责和顺序约束，不锁定未来的状态枚举名称。

取消必须遵守以下规则：

- **取消请求不等于已经停止。** 区分请求取消、正在收尾和已经确认退出。
- 发布结局前到达的取消，不能被迟到的成功覆盖；已经发布的结局不因迟到回调重复改变。
- 合作取消超过宽限时可以发布带清理警告的取消结果，但仍要明确存在未完成收尾的工作，不能展示为已强制停止。
- 未完成收尾的 Worker 仍需有所有者，不能像普通已完成记录一样淘汰；也不能借超时反复释放名额，无限制增加尚未退出的工作。
- 初始化迟到时仍负责关闭最终创建的会话；迟到结果不能重新挂回已释放会话或再次发布结局。

同进程执行不提供强杀、文件系统隔离或副作用回滚。工具授权、项目可信边界和并行写域约束继续适用。

## 结果与通知分离

**结果先成立，通知后发送。**

- 完整结果独立保存，包含失败或取消时的部分输出及用量，不把 SDK 转录当作唯一结果读取协议。
- 后台结果需要覆盖短正文，而不只是超过内联预算的长正文；保存格式与元数据布局尚待细化。
- 保存失败必须显式报告，不能生成成功交付通知或虚构可读取路径，也不能掩盖原执行错误和清理警告。
- SDK 会话释放、父上下文压缩、通知延迟或重复，都不应使已保存结果失去可读性。
- 通知只提供有界摘要、任务标识和读取引用。读取结果不依赖通知是否已经投递。
- 投递由任务结束及父会话生命周期事件协调，在安全时机进行；不要求模型 sleep 或轮询任务。
- 不把通知传输当作 exactly-once 保证；重复通知不能触发任务重复执行。具体去重、确认及重发策略待接口设计确定。

“不跨进程恢复执行”与“结果文件可以保留”是两件事。保留文件不表示任务仍在运行，也不表示 SDK 会话可以恢复。

## 与当前实现的关系

当前插件继续采用前台链路。本方案只记录后续设计方向，不新增后台入口或工具参数。

| 当前模块 | 可以复用的部分 | 需要另行设计的边界 |
|---|---|---|
| `src/request.ts`、工具授权与信任模块 | 定义、模型、上下文及工具选择 | 接受任务时明确归属与权限快照 |
| `src/runner.ts` | 单次会话执行、事件记账、合作取消和释放 | 接收后台任务自己的取消信号，处理未完成收尾的所有权 |
| `src/outcome.ts` | 不含 SDK 句柄的结果数据 | 不把执行结果与通知状态混在一起 |
| `src/result-output.ts` | 正文格式、内联预算、唯一 UTF-8 文件 | 当前仅长结果落盘，不能直接视为完整的后台 ResultStore |
| `src/executor.ts` | 限流、排队、取消及关闭的已有经验 | 当前是前台调用所有者，不等于已实现后台 Supervisor |

## 实现前仍需确定

- 提交、接受确认、结果读取和显式取消的接口；本文不规定工具名或参数。
- 父会话身份与扩展实例的归属边界，以及父端生命周期事件的具体适配。
- 通知是否自动唤醒父模型、如何去重，以及人类如何查看和停止活跃任务。
- 已完成任务元数据和结果文件的保留、清理及读取范围。
- 并发名额、取消宽限与未完成收尾的容量策略，确保限流仍有真实含义。

后续实现的验收重点应包括：跨父回合而不串父会话、排队与初始化阶段取消、迟到回调、非合作收尾、结果保存失败、通知延迟或重复，以及会话释放后完整结果仍可读取。
