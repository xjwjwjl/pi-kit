# 前端 Mock 数据开发指南

## 决策：选场景

| 条件 | 走哪个场景 |
|---|---|
| 能访问后端源码 | 场景 A：对齐已实现接口 |
| 后端未实现或无法访问源码 | 场景 B：mock 即 API 契约 |

---

## 场景 A：后端已实现 → 对齐接口

按以下顺序读代码，每步确认一项关键信息。

### Step 1：后端 Model / DTO → 取字段名

- **序列化 tag 决定字段名**，不用代码变量名。Go 结构体看 `json:"field_name"`。
- 类型也以 tag 为准（string / int / bool / 数组 / 对象）。

### Step 2：后端 Handler / Controller → 确认外层包裹

读后端 handler 的返回语句，确定响应包裹层级：

1. handler 直接 `return` 数据，还是包了一层对象？
2. 分页接口是否额外包了 `list` / `total` 等字段？
3. 项目统一响应格式是什么（如 `{code, data, msg}`）？

mock 按同样的层级和格式构造，**以实际前端拿到的响应形态为准**。

### Step 3：前端 API 封装 → 确认 URL 和方法

读前端 API 封装文件，确认真实请求路径和 GET/POST/PUT/DELETE。

### Step 4：前端页面消费方式 → 确认 data 内部结构

看页面拿到响应后的处理代码，归为三种模式：

| 模式 | 特征 | mock 结构示例 |
|---|---|---|
| 直接使用 | 整个响应数据赋给变量使用 | `[...]` 或 `{...}` |
| 取子字段 | 从响应中取某个字段（如 `.list`、`.items`） | `{ list: [...] }` |
| 遍历转换 | 对响应数据做 map / forEach 加工 | 对齐加工逻辑中引用的字段 |

### Step 5：编写 mock 文件

对齐以上四处确认的字段名、包裹格式、URL、内部结构。

---

## 场景 B：后端未实现 → 前端先行

Mock 就是前后端协商的 API 契约文档。

### Step 1：按需求定义接口轮廓

根据 UI 设计稿或功能需求，确定：
- 接口 URL、请求方法、参数
- 页面需要展示哪些字段
- 数据是列表、详情还是图表（决定返回形态）

### Step 2：定义字段名

- 同一实体在不同接口中使用**一致的字段名**。
- 字段命名风格对齐后端约定（如 snake_case）。

### Step 3：标记为草案

mock 文件中注释 `// TODO: 后端未实现，字段名和结构待与后端确认`。

### Step 4：编写 mock 文件

按 Step 1 的接口轮廓和项目统一的响应包裹格式编写 mock。

## Mock 目录组织

在**前端项目根目录**下建 `src/mock/`：

```
src/mock/
├── index.ts            # 汇总导出（vite-plugin-mock 入口）
├── api/                # 接口 mock，按模块拆文件
│   ├── user.ts
│   ├── device.ts
│   └── dashboard.ts
└── data/               # 静态数据（路由、菜单、字典等）
    ├── routes.ts
    └── dict.ts
```

- **按模块拆文件**，不要一个文件塞所有接口
- **接口 mock 放 `api/`**，静态配置 mock 放 `data/`**，避免路由 mock 和业务接口 mock 混在一起
- **命名与前端 API 封装文件对应**（`api/user.ts` ↔ `mock/api/user.ts`），方便查找

## 特殊数据类型

图表、分页等数据格式取决于**页面实现方案**。先读页面代码理解消费方式，再反推 mock 结构。

### 图表 / 时间序列

读页面的图表初始化代码，确认：
- 用的什么图表库（ECharts、Chart.js 等），不同库的 `series.data` 格式可能不同
- 数据是直接赋值给 `option.series[].data`，还是先做格式转换（如交叉 `x` 轴和 `series` 拼出 `[x, y]` 点）
- 时间轴是独立字段（`dates` / `xAxis`）还是内嵌在每项数据中

mock 结构对齐转换前的原始数据格式，不是转换后的图表配置格式。

### 分页数据

读页面的分页组件和列表赋值代码，确认：
- 列表字段名（常见 `list` / `items` / `records`）
- 总数字段名（常见 `total` / `totalCount`）
- 是否需要 `page` / `pageSize` 回传

mock 按同样字段构造。

## 常见问题排查

### 页面数据为空

- **条件渲染未命中**：列/区块用 `v-if` 等依赖某字段值，mock 值不满足条件 → 搜条件逻辑，用合法值。
- **store 初始值阻止加载**：首次加载依赖状态管理的值，但初始为 `null` / `undefined` → 给初始值设合理默认值。注意防御逻辑和模板条件分支。

### 数字值显示异常（0 / NaN）

前端 formatter 做了单位换算（字节转 GB、分转元等），mock 值量级不对 → 看 formatter 运算逻辑，填入正确量级。

### 图表不渲染

mock 多包了一层 → 回到场景 A Step 4，对照前端如何解包响应。

### 路由 / 菜单配置中组件路径错误

Mock 中的组件路径必须指向**实际存在的文件**，不能猜测为 `index.vue`。

有子级的父菜单，其组件必须指向包含路由出口（如 `<router-view>`）的容器组件。

```bash
# 列出实际文件（别猜 index.vue）
find src/views -name "*.vue" | sed 's|src/||'
```
